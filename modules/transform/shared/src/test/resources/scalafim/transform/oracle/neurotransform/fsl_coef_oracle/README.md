# Native FNIRT coefficient-file reference fixtures

Generated by `tools/generate_fsl_coef_oracle.py` with pinned FSL 5.0.9 `fnirt`,
`fnirtfileutils`, and `applywarp`, without calling neurotransform. The manifest
records the Docker image digest, the exact commands, and the file hashes.

There are ten cases. Eight use cubic splines (intent 2007): every
source/reference handedness pair, each run with and without `--aff`. The two
`*_quad` cases repeat two of those grids with `--splineorder=2` (quadratic,
intent 2009), covering both reference handedness, with and without `--aff`, and
an axis with knot spacing 1. The `--aff` matrix is a world-aligning FLIRT matrix
combined with a small rotation, anisotropic scaling, and translation. Source
and reference grids differ in dimensions, spacing, obliquity, and origin. Knot
spacings vary from 1 to 5 voxels.

Quadratic coefficient counts do not always follow the cubic rule
(`ceil((N+1)/k) + 2`); decoding uses the same knot offsets for both orders.

Each case contains:

* `coef.nii.gz`: the FNIRT `--cout` output.
* `field_noaff` and `field_aff`: the fnirtfileutils output without and with
  `--withaff`.
* `native_coord0..2`: applywarp `--warp=coef` applied to the source RAS
  coordinate ramps.
* `native_support`: the same for the two-voxel source-interior indicator. It
  equals 1 where the ramps are exact.
* `native_source`: the same for the source image.

Decoder checks should use a tolerance of 1e-4 mm on the fields and the
interior-support coordinates. The reference decoder reaches at most 1e-6 on
the fields and 7e-6 on the coordinates.

These fixtures provide evidence of how the coefficient files are interpreted by
the recorded producer. They do not qualify FNIRT registration accuracy.
