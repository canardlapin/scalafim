## Reader contract

Accepts: ZIP with STORED members only (method 0), top-level `*.npy` names, no data descriptor, no
encryption, no zip64, no archive comment, matching local/central headers, valid CRC-32; `.npy` v1.0,
header `descr` in `{<f8, <i4}`, `fortran_order False`, exact data length.
Refuses (typed `NpzError`): `Truncated`, `NotZip`, `Zip64OrMultiDisk`, `Encrypted`,
`CompressedMember`, `DataDescriptor`, `SizeMismatch`, `CrcMismatch`, `DuplicateMember`,
`UnknownMember`, `LocalHeaderMismatch`, `BadMagic`, `UnsupportedNpyVersion` (v2/v3 and 1.x),
`MalformedHeader`, `UnsupportedDtype`, `FortranOrder`, `ShapeOverflow`, `DataLengthMismatch`.

## Binding order (every step a typed `IngestRefusal`)

1. manifest parse, `schema == phrf-gen-npz-1`;
2. `root_kind`, `root_hex` against the caller-supplied expectation; the manifest denylist must equal
   the denylist pinned in `IngestExpectation`; `root_denylisted == false` and the root (and its low 32
   bits) recomputed against the pinned denylist;
3. `generator_code_sha256` against the caller-supplied frozen value;
4. cell spec: id, kind, `n_voxels`, `n_pool`, `tr`, `tr_aligned_onsets`, and dataset index;
   then the four stream seeds are re-derived (`Seeds`, port of `seeds.py`: SplitMix64 over
   `fnv1a64(cell_id)`, dataset, purpose on unsigned 64-bit) and compared as exact digit strings with
   both manifest copies (read from raw JSON, never via `Double`), the manifest hit flags must equal
   the recomputed hits, and a recomputed hit is `StreamDenylisted`;
5. SHA-256 of the whole npz against `npz_sha256`;
6. strict parse; each member's raw bytes against `arrays[name].npy_sha256`, dtype and shape against
   the manifest; arrays outside the schema list (common plus trial-only) refused; missing arrays
   refused;
7. cross-array dimensions (V, T, N, P, pool) consistent.

`FitInputs` has `private[ingest]` constructor and no truth field; truth arrays are only in
`ScoreTruth`. `yPool` is `None` for condition cells.

## Review-fix round (M1, L1-L6)

- M1: seeds re-derived and compared exactly, hits recomputed, denylist pinned, `dataset` added to
  `IngestExpectation`. Tests: derivation equals `seeds.py` outputs; a seed above 2^53 whose digits
  change under Double rounding is refused when tampered to the rounded digits and to a +-1 value that
  Double cannot distinguish; seed digit, check-copy seed, dataset, missing purpose, duplicate member,
  flipped hit flag, weakened and extra denylist, and a genuinely denylisted derived seed (low 32 bits).
- L1: header regex is the exact numpy v1.0 dict form with strict shape grammar; padding to 64 bytes
  enforced; non-numeric, leading-zero and malformed shapes give `MalformedHeader`.
- L2: central directory must end exactly at the end record; local entries must tile `[0, cdStart)`;
  tests for swapped offsets, gaps, leading bytes, `../` and absolute names.
- L3: SHA-256 vectors at 55, 63, 64, 119, 120 bytes (hashlib-derived).
- L4: documented that tuning code receives `FitInputs` only (Records.scala, README).
- L5: added to `root.aggregate` and to the root README.
- L6: `dependsOn(model, fit)` dropped.

Coverage of the obligations (design section 6, S1):

- golden parse of a tiny in-test STORED npz (f8, i4, scalar, 1-D, 3-D) and of embedded real
  `phrf_gen.io.npz_bytes` output (JVM and JS), plus real generator files from a HARNESS-root
  run (`jvm/src/test/resources/fixtures/`, trial and condition cell). A JVM test regenerates both
  with the generator and asserts byte equality when python3, numpy and scipy are present
  (it ran and passed in `phrf-s1-test6`);
- every refusal: DEFLATE (also on a real file re-zipped and re-signed), other methods, encrypted,
  data descriptor, bad CRC, zip64, comment, local header mismatch, unknown and duplicate members,
  f4/>f8/i8/u4/object/string dtypes, Fortran order, npy v2/v3/1.1, bad magic, length mismatch,
  shape overflow, malformed header, and every strict prefix of a valid npz;
- hash mismatch: whole-file byte flips (at four positions on the real file; also re-signed so the
  CRC catches it), per-array hash by name;
- manifest tamper: schema, root_kind (three values), root_hex, code hash, `npz_sha256`,
  `root_denylisted`, recomputed root hit, stream hit, each cell field including
  `tr_aligned_onsets`, array dtype and shape, array removed from or added to the manifest;
- JVM-vs-JS identical byte-parser results: the shared golden test compares a SHA-256 over a
  bit-exact rendering of every decoded value to a constant computed independently in Python; the
  same test runs on both platforms and passes on both;
- `FitInputs` exposes no truth field: `Mirror` field labels are disjoint from the truth set and
  equal `ScoreTruth`'s fields exactly; `compileErrors` shows each truth selector does not compile
  on a `FitInputs`; the constructor cannot be called outside the package.

## Deviations from the design

- Ledger (`input_sha256` per dataset into a dataset ledger) is not built here: `BoundDataset`
  carries `inputSha256` and `arrayHashes`, and the ledger belongs with S7. The per-arm derived-input
  hash is S2.
- The module has no project dependencies yet. The design lists `fit`, `dataset`, `hrf`, `model` and
  `ar`; they are added when a later slice needs them.
- The adaptor-output (GLMsingle STORED) fixture is not covered: the adaptor
  (`from_generator.py`, S6) does not exist yet. The reader already accepts that format class.
- The real-file tests in the shared module cannot embed 200 KB fixtures, so they sit in `jvm`; the
  shared suite binds a tiny synthetic generator-shaped dataset on both platforms instead.
