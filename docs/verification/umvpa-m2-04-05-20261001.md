# UMVPA M2.04 and M2.05 owner-local evidence

This slice adds `RelationRdm`, operating only on the M2 typed
`RelationSet`/`PairingDesign` contract.  Its baseline constructor creates all
ordered, all-distinct partition pairs, uses a fixed identity neural metric,
retains signed squared cross-products, records the ordered effect ordinals, and
divides by the neural feature count only when `IdentityRdmPolicy` requests it.
The word Crossnobis is intentionally absent from this baseline API because no
residual precision is estimated here.  A pair requiring a non-estimable effect
returns a visible `NotEstimable` cell rather than a zero or a different metric.

`ResidualPrecisionMetric` is a separate route.  It wraps the admitted
diagonal-plus-low-rank `ResidualCovariance` precision operator and retains a
declared-conditional, descriptive, or rejected admission. The conditional form
requires bound residual/precision/df capabilities and names the actual source,
declared training axis, residual receipt, estimator and degrees of freedom.
It supplies no independently verified training-scope or independence proof.
It has no fallback to total
covariance or identity.  Its declared maximum column count refuses a request
that would exceed the owned materialization/application budget.

The owner-local suites supply independent small dense expectations: an
identity signed two-partition RDM, a four-effect/three-partition condensed-order
oracle matching frozen legacy values, and the dense inverse of
`[[3, 2], [2, 7]]`. Forward and adjoint column budgets are both exercised.
See `umvpa-five-20261001.md` for the final owning-module gates and source identity.
