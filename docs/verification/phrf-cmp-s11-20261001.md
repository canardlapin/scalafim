## Comparator to fmrireg mapping (condition gate)

Common fmrireg construction: `fmridataset::fmri_frame` with an observation `start_time` column of 0;
`event_model(onset ~ hrf(cond, basis = B), block = ~run, sampling_frame = sf, precision = 0.1)`;
`baseline_model(basis = "poly", degree = 2, sframe = sf, intercept = "runwise")`;
`fmri_model(em, bm, dataset = frame)`; `fmri_lm(fm, control = fmri_lm_control(estimation =
estimation_spec("joint"), noise = noise_spec("ar1", pooling = "global")))` with phi fixed (below).

| Protocol comparator | fmrireg basis `B` | Event coefficients | E-resp reconstruction |
| --- | --- | --- | --- |
| CAN: `HrfKind.Spmg1`, SPM double gamma | `"spmg1"` (`HRF_SPMG1`, `P1=5, P2=15, A1=1/120`) | 1 per condition (A, B) | `beta_c * h(tau)` |
| INF3: `Spmg3`, canonical + temporal + dispersion derivatives | `"spmg3"` (`HRF_SPMG3`) | 3 per condition, order b01 canonical, b02 temporal derivative, b03 dispersion derivative | `sum_k beta_(c,k) h_k(tau)` over all three columns |
| FIR: `Hrfs.fir(H/1 s, H)`, 1 s bins, unpenalised | `getHRF("fir", nbasis = 32, span = 32)`, H = 32 s | 32 per condition (bins 1..32), unpenalised OLS/GLS | `beta_(c, floor(tau) + 1)` for `0 <= tau < 32`, 0 at `tau = 32` |

Estimation scope is `joint` (one coefficient vector shared across runs), not `runwise_meta`: the
condition gate is a single joint GLS on concatenated whitened runs. `runwise_meta` would fit each run
separately and pool, which is a different estimator.

Kernel definitions (fmrihrf 0.4.0, matched by an independent hand implementation to 1.6e-16 for SPMG1
and 9.5e-14 for SPMG3):

- SPMG1: `exp(-t) (t^5/120 - t^15/(6 * 15!))`, 0 for t < 0.
- SPMG3 col 2: analytic d/dt of SPMG1.
- SPMG3 col 3: `mass * (dgamma(t; shape 6, scale 1) - dgamma(t; shape 6/1.01, scale 1.01)) / 0.01`, `mass = A1 * Gamma(6) = 1`. This is the fmrihrf definition (mean and mass fixed), not the SPM12 dispersion
  convention. It is also the `spmg1DispersionDeriv` formula in `HrfFunctions.scala` (read, not run).
- Columns are not orthogonalised or independently scaled.

Fixtures: see Layout. `X_*` is the unwhitened design (event columns then baseline); `beta_*` holds the
event coefficients (rows) by voxel; `eresp_*` is on tau 0..32 step 0.25 with columns `<cond>.<voxel>`;
`kernel_*` gives the raw basis values on the same tau grid.

**Primary parity check is E-resp, because it is scale-invariant.** Betas are gated after rescaling
for the kernel normalisation (see gotcha 1).

## Trial gate

Whitened inputs (exact-first in the primary directories): `Y_white`, `X_trial_white` (36 canonical
single-trial regressors, fmrireg `trialwise(basis = "spmg1")`, unwhitened copy in `X_trial.csv`),
`F_white` (whitened baseline).

| Comparator | Reference | Notes |
| --- | --- | --- |
| LSA | `fmrilss::lsa(Y_white, X_trial_white, Z = F_white)` | R path is `lm.fit` on `[X, Z]`; `method = "cpp"` is an alias of the same code. Independence is weak: the in-R check solves the normal equations (not `lm.fit`), but both are the same least-squares problem on the same inputs, so the check guards against wiring errors (argument order, Z handling), not against a conceptual error |
| LSS | `fmrilss::lss(Y_white, X_trial_white, Z = F_white, method = "r_optimized")` | Trial i plus ONE summed regressor of all other trials plus F. Cross-checked against `method = "naive"` and an explicit loop. fmrilss warns "no intercept detected" because the whitened run constants are not all ones; harmless and suppressed in the script |
| rLSS | Dense penalized solve, plus a closed form, both in R | Design v2.1 section 2.2. Below |

rLSS reference (condition-centred ridge on the trial deviation, protocol/design F4). For trial i in
condition c(i), regress `y_white` on `D = [X_1 .. X_C, x_i, F]`, where `X_c` is the sum of the
whitened single-trial regressors of condition c (including trial i); only the `x_i` coefficient
(`delta_i`) is penalised with ridge r. Dense: `beta = solve(D'D + diag(0,..,0, r, 0,..,0), D'y)`; the
trial amplitude is `m_hat_c(i) + delta_hat_i`. The closed form `delta_hat = x~'y / (x~'x~ + r)`,
`x~` the residual of `x_i` on `[X_1..X_C, F]`, with `m_hat` refit on `y - x_i delta_hat`, agrees with
the dense solve to at most 3.2e-15 over all 36 trials and 6 ridges in all four trial directories. Ridge grid: `r = mean(q) * {0, 0.01, 0.1,
1, 10, 100}` with `q_i = x~_i'x~_i`; `mean(q)` per cell and convention is in `meta.json` (`cells.*.mean_q`). Files (per trial directory): `rlss_ridges.csv`
(k, r, edf), `rlss_amp.csv` and `rlss_delta.csv` (rows `k:trial_NN`), `rlss_lss_equivalent.csv`.

LSS-equivalence flag: one group (all trials), `r = 0` reproduces `fmrilss::lss` to at most 1.6e-15. This is
the reference for the S4 flag.

df-mapping reference (design section 2.2): `edf(p) = mean_i q_i/(q_i + p)` with `q_i` in `df_q.csv`.
`df_edf_grid.csv` gives edf at 9 log-spaced p; `df_inverse.csv` gives r for targets edf = 0.1..0.9 by
root finding on log r (round trip 1.7e-16). Note: for the shape-free canonical `q_i` used here, the
mapping `edf(r_k) = edf(p_k)` is the identity `r_k = p_k` whenever `p_k` is already on the `q` scale;
the non-trivial content is the inverse in `df_inverse.csv`. The scale factor between PHRF's `lambda`
and `p` is S4's to derive and is not tested here.

## fmrireg and a fixed external phi

**fmrireg cannot accept a fixed external phi through its public API.** `fmri_lm()` takes noise
structure only through `noise_spec(struct, p, q, iter_gls, pooling, shared_estimator, exact_first,
...)`, which always estimates the AR coefficients (design-corrected pooled autocovariance by default).
`noise_spec(pooling = "global")` yields one pooled coefficient, which is the protocol's shared
whitening shape, but its value is estimated.

Internally, `runwise_lm_impl`, `chunkwise_lm` and `process_run_standard` take `phi_fixed`, but the only
producer in the joint path is `.estimate_shared_ar_parameters()` (`R/fmrilm.R`, called when
`cfg$ar$global`). Two workarounds were used and cross-checked against each other:

1. **Internal override (used to produce the fixtures).** For the duration of one `fmri_lm()` call the
   internal `fmrireg:::.estimate_shared_ar_parameters` is replaced by a function returning 0.3125.
   This runs fmrireg's own whitening and solver with the given phi; `ar_parameters(fit)` returns
   exactly 0.3125, asserted in the script. It depends on a private name, so it can break on any
   fmrireg change; the generator fails loudly if so.
2. **Pre-whitening outside fmrireg.** Whiten Y and fmrireg's own `design_matrix(fm)` (event columns
   and baseline) with the filter above, then `lm.fit`. fmrireg's `fit_glm_on_transformed_series()` does
   NOT serve here: it whitens neither the design nor accepts a whitened design (the design is rebuilt
   from events), so feeding it whitened Y alone fits a different model. The pre-whitened route is
   therefore plain OLS outside fmrireg.

Cross-check result: route 1 and route 2 agree to at most 2.3e-16 relative (all arms, both cells, both conventions).

fmrilss likewise has no fixed-phi argument (`prewhiten_options` estimates via fmriAR), so LSA and LSS
were run on externally whitened inputs with `prewhiten = NULL`. This matches the protocol, where all
native arms share one whitened array.

## What could not be matched exactly, and gotchas for the Scala side

1. **Peak normalisation.** Protocol section 4 describes CAN as "SPM double gamma, peak-normalized".
   fmrihrf `HRF_SPMG1`, the fixtures and the Scala `spmg1` formula are raw (peak
   0.17544119701700001). E-resp is scale-invariant and is the primary parity check. Betas are gated
   after rescaling: divide fixture betas by the peak (raw/peak), or normalise the Scala kernel; for
   INF3 all three columns scale by the same canonical-column scalar. **The protocol wording needs one
   line saying which convention applies to betas.**
2. **Support, 24 s.** fmrihrf SPMG kernels carry `span = 24`: the convolution uses lag in [0, 24],
   24 inclusive, and is zero beyond, although the double-gamma undershoot is non-zero past 24 s (an
   absolute design difference of about 2e-3 against a 0.175 peak in one exploratory comparison).
   `fmrireg::fitted_hrf` E-resp is NOT truncated: it evaluates the raw kernel out to 32 s (confirmed:
   it matches the untruncated hand kernel to 1.7e-16 on tau 0..32). Scala must reproduce both: truncated
   convolution for the design and betas, untruncated kernel for E-resp reconstruction. The truncation
   must be identical for all native arms (CAN, INF3, LSA, LSS, rLSS, PHRF input), or the arms are not
   fitted on the same design.
3. **Convolution grid.** fmrireg's default `conv` method quantises onsets to its `precision` grid and
   is accurate to about 1e-3 against exact kernels only when onsets are off-grid. The generator and
   protocol place onsets on a 0.1 s grid; with 0.1 s onsets, fmrireg at precision 0.25 is off by about
   1.5e-3 (reviewer measurement 1.46e-3; not re-measured here), while **precision 0.1 matches exact-lag convolution to 1e-13 or better**. All fixtures use
   `precision = 0.1`. Onsets finer than 0.1 s would need a finer precision. The overlapping-events cell
   `cond_close` (gaps 0.1 to 0.5 s) exercises shared FIR bins and summed overlapping kernels.
4. **Scan-time origin.** fmrireg's `sampling_frame` default is `start_time = TR/2`. The fixtures use 0.
   A Scala design that places scan k at `(k + 0.5) TR` will not match.
5. **First-observation convention.** The spec fixes it: design v2.1 section 2.0.4 sets
   `WhiteningPlan.global(..., exactFirstAr1 = true)`, which is also the default and the S0 spike
   setting. The primary fixtures use exact-first (`z_1 = sqrt(1 - phi^2) x_1`, fmrireg
   `exact_first = TRUE`). Identity-first is provided as a secondary variant for every arm in the
   `identity_first/` directories.
6. **Fixed phi route is internal to fmrireg** (above). A fmrireg upgrade can break regeneration, not
   the committed fixtures.
7. **Scope of "fmrireg parity".** The fixtures pin fmrireg's joint GLS on a fixed phi. They do not test
   fmrireg's phi estimation, which differs from the protocol's pooled-FIR-residual AR(1) and is out of
   S11's scope (O1 supplies phi to both sides).
8. **Not covered:** INF2 (secondary), FIRp, PHRF-can, voxelwise or per-run phi, AR(2), unequal run
   lengths, censoring. The df mapping `p_k` to PHRF `lambda` scale factor (S4).
9. **Fixtures carry no Scala-side verdict.** Whether Scala meets 1e-8 and 1e-10 is S11's second half.

### Owner decisions and how parity accounts for them

| Decision | Accounting in the gate |
| --- | --- |
| 1. FIR E-resp piecewise constant | `eresp_fir.csv` is already piecewise constant (R `fitted_hrf` = `beta_(c, floor(tau)+1)`, 0 at 32). COND compares FIR E-resp on the whole 0-32 s grid at 1e-8 (achieved 6.9e-15), and KDES compares the FIR basis exactly (0). No fixture change. |
| 2. CAN and INF3 E-resp truncated at 24 s | The R fixtures stay untruncated to 32 s (they match `fitted_hrf`). COND restricts the E-resp comparison to tau <= 24 s and asserts the Scala E-resp is exactly 0 for every tau > 24 s; KDES does the same for the kernels. 24-32 s is a documented, deliberate deviation from fmrireg (`fitted_hrf`), not a parity claim. The 24 s point is inclusive, matching the design-kernel span (lag in [0, 24]). |
| 3. PHRF lowers on a 0.1 s grid | The parity fixtures are on the 0.1 s onset grid with fmrireg `precision = 0.1` (cells `cond`, `cond_close`, `trial/ts`), and the native designs use exact-lag convolution, so they are unaffected by the PHRF grid. PHRF itself has no R reference, so there is no PHRF-grid parity row; the 0.1 s-on-grid design agreement is covered by COND/KDES (design abs <= 2.3e-13). |
| 4. rLSS matched to PHRF on true trace edf | The rLSS estimator and its amplitude-block trace edf are checked against dense references: `RidgeLssSuite` at 1e-10 (worst 2.4e-13 amplitudes and deviations, 3.0e-16 edf) on JVM and JS, and TRIAL at 1e-10 against the R dense solve. The R fixtures' `df_*` files hold the information-ratio `mean_i q_i/(q_i + p)`, which TRIAL also reproduces (<= 3.4e-16); that is the penalty-scale mapping, not the matching edf, so no R fixture for the amplitude-block trace exists. The dense solve is its reference. |

R fixtures were not regenerated: none of the four decisions changes what the R side computes, only
which slice of it the Scala side compares.

### Caveats

- The condition parity uses raw kernels and raw betas (gotcha 1); the design doc note of 2026-10-02
  already records this, so no rescaling is applied.
- Whitening agrees bit for bit (error 0) because the Scala and R filters perform the same
  operations on the same `%.17g` inputs; the 1e-10 tolerance is not exercised there.
- A failure in any check above would label the arm "parity-failed" and block v0; none fails.
