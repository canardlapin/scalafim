## Behaviour

1. **Verification and refusal.** Refuses (exit 2, typed `Refusal`) unless: schema `phrf-gen-npz-1`; whole-file `npz_sha256`; per-member `npy_sha256`, dtype and shape; file name; `root_kind` in {harness, pilot}; root and stream denylist flags clear; recorded streams re-derived from `root_hex` (normative `seeds.py`); optional `--expect-generator-sha`, `--expect-n-pool`, `--expect-n-voxels` (the S7 runner config freezes the pilot cell table: 40 scored / 4000 pool for T-TX-fast and T-TX-jit, T-TS-fast as the design specifies, and passes these flags); manifest `n_voxels`, `n_pool`, `n_samples` cross-checked against the `y`/`y_pool` shapes and `sample_time` spacing (n*tr per run) before GLMsingle runs; any missing or malformed manifest key is a typed refusal (exit 2); every condition must occur in every run and every `ev_run` must be present in `run_id`; cell kind `trial` and `tr_aligned_onsets` true; onsets on the TR grid; n_pool >= 1.
2. **Design.** The wrapper's TR-resolution `build_design`; realized onset quantization must be exactly 0 (else refusal).
3. **Baseline.** `+100.0` added in float64 to every sample of `y` (scored) and `y_pool` (pool), for the GLMsingle input only. Scored voxels first, pool after.
4. **Run.** In-process `run_glmsingle(..., types="BD", threads=1, seed=<audit stream seed>)` under a SIGALRM wall-clock timeout (default 900 s; exit 4). `GlmSingleTimeout` is a `BaseException`, so a broad `except Exception` inside the wrapper cannot swallow it. This is best effort: hard enforcement is the Scala-side process kill (S6 Scala bridge or S7). Thread env vars are pinned to 1 before numpy loads.
5. **Units.** `beta_data = beta_psc / 100 * |meanvol| * peak(h_used)` in float64, from GLMsingle's own returned `meanvol`, psc betas and HRF library.
6. **Output.** `<id>.glmsingle.npz` (STORED, sorted members, fixed timestamps, `.npy` v1.0, `<f8` only) and `<id>.glmsingle.meta.json`.

## Deviations

- The generator manifest records only the streams used by generation (design, truth, noise, nullcal); there is no `audit` entry. The bridge derives the `audit` seed from `root_hex`, cell id and dataset with the normative `seeds.stream_seed`, re-checks the recorded streams against it, and checks the audit seed against the denylist. GLMsingle does not consume the seed (determinism comes from the algorithm), so it is provenance only.
- The receipt JSON stays at `tools/phrf-comparison/glmsingle/converter/from_generator_converter.json`, not `results/from_generator_converter.json` as the S6 row names it (S6's reservation covers `converter/` only). **Use the `converter/` path in the v0 frozen list.**
- Output betas are chronological (GLMsingle convention) with `trial_event_index`, not pre-reordered; the reorder to input order is for the Scala bridge (S6 row: "E-trial in input order").
- Delta events (`ev_duration` 0) use `stimdur = tr` (1 s), as in v0b.
- Timeout uses SIGALRM (main thread, POSIX); a call blocked in a C extension is interrupted at the next bytecode boundary.
- Harness datasets at pilot size use a modified `Cell` (n_voxels, n_pool), since the shipped harness cell has 200/100.

## Scala bridge (`GlmSingleBridge.scala`), 2026-10-03

Code: `modules/phrf-comparison/jvm/src/main/scala/scalafim/phrfcmp/run/GlmSingleBridge.scala` (JVM only). Tests: `.../jvm/src/test/scala/scalafim/phrfcmp/run/GlmSingleBridgeSuite.scala` (14 tests). ### Contract

`GlmSingleBridge.run(GlmSingleInputs, GlmSingleConfig): Either[GlmSingleRefusal, GlmSingleOutcome]`. The outcome holds `Vector[VoxelOutcome[TrialEstimate]]` (scored voxels, E-trial in INPUT trial order: `out(v)(trial_event_index(k)) = d_beta_data(v, k)`), the CPU figures, wall time, the output and input SHA-256 and the thread-pinning description. A non-finite voxel is `Failed` alone; every bridge-level refusal maps to all-voxel `Failed` through `GlmSingleRefusal.asVoxels` (design 2.3). `GlmSingleOutcome.toString` is redacted.

**Binding decision.** GLMsingle does its own preprocessing, so the bridge does not bind to `CommonPreparation`. It binds to the dataset by SHA-256 of the generator `.npz` (optionally against the caller's expected hash, which S7 takes from `BoundDataset.inputSha256`) and against the `input.npz_sha256` the Python side recorded. The `+100` offset stays in Python; the Scala side only reads `d_beta_data`.

**RAM scratch (owner decision 2026-10-03).** One scratch per invocation.
- macOS: `hdiutil attach -nomount ram://<sectors>` (128 MB), `newfs_hfs`, `mount -t hfs -o nobrowse,nosuid,nodev` on a private 0700 mountpoint named `phrfcmp-ram-<ownerPid>-<random>`, a `.metadata_never_index` marker, mode 0700 on the root (applied and re-read before any child starts; failure is fatal). `mdutil -i off` was tried by hand and needs root, so it is not used; `nobrowse` plus the marker is the indexing guard (logged as an event). `diskutil erasevolume` is not needed. Teardown order: process-group kill, wipe (delete every file, then assert no regular file remains), `umount`, `hdiutil detach` (retries; neither the unmount nor the detach is ever forced), remove the mountpoint, verify path and device gone. `hdiutil detach` alone fails with "Resource busy" on a volume mounted by `mount(8)`; the explicit `umount` first is required.
- Linux: private 0700 directory under `/dev/shm`, required to be a tmpfs mount; wiped and removed, then verified. **Not exercised on this host** (the Trillium path is untested here).
- Any other host, or missing `hdiutil` / unwritable `/dev/shm`: typed `NoRamScratch`; the child is never started (tested). There is no disk fallback.
- Confinement: the child gets a cleared environment (no inherited variables, so the root pipe variables cannot reach it) and its working directory, `--out`, `TMPDIR/TMP/TEMP`, `HOME`, `XDG_*`, `MPLCONFIGDIR`, `NUMBA_CACHE_DIR`, `JOBLIB_TEMP_FOLDER`, `PYTHONUSERBASE` all inside the scratch; `MPLBACKEND=Agg`, `PYTHONDONTWRITEBYTECODE=1`. Thread pins: `OMP`, `MKL`, `OPENBLAS`, `NUMEXPR`, `VECLIB_MAXIMUM`, `NUMBA` = 1.
- **Finding:** GLMsingle writes `GLMestimatesingletrialoutputs/{DESIGNINFO,RUNWISEFIR}.npy` (design-derived and FIR-fit arrays) and an empty `GLMestimatesingletrialfigures/` into the **current working directory** even with `wantfileoutputs=[0,0,0,0]`, `outputdir=None`, `figuredir=None` (this is what left the untracked `tools/phrf-comparison/glmsingle/GLMestimatesingletrialoutputs/` in the shared worktree). Figures are disabled by the wrapper; the directory leak is closed by making the scratch the child's cwd. Those two untracked directories predate this slice and were not touched.
- Every step is a `ScratchEvent` (created, device attached, formatted, mounted, indexing guard, child started, process group killed with survivor count, wiped with file/byte/residue counts, unmounted, detached, removed, verified, step failed) delivered to a `ScratchHook` (paths, counts and device names only, never contents). A hook that throws does not stop cleanup (tested).
- A scratch that cannot be verified gone overrides the run result with `ScratchResidue(..., prior)`; no result is returned from such a host.

**Timeout and kill.** The child is started through `perl -e 'setpgrp(0,0); exec @ARGV'` so its pid is the process-group id. The JVM enforces the wall-clock limit; on expiry, and on every other exit path, `kill -KILL -- -<pgid>` is sent, membership is re-checked with `pgrep -g` until empty, then the scratch is released. The Python SIGALRM timeout remains best effort. Timeout test: a stub with a background grandchild; both pids dead after the refusal, scratch gone.

**CPU capture (two figures, two purposes; see the review round).** `/usr/bin/time -p` around the child (rusage of the child and its waited descendants), the polled process-tree CPU, and the sidecar `cpu_s`. `guardCpuSeconds` (rusage-first, polled if the child was killed) is for the section 5.2 guard only; `timingCpuSeconds` (sidecar `cpu_s`, the GLMsingle call alone, comparable with the in-process native arms) is for the timing endpoint only.
