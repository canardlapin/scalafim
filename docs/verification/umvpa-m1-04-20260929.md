# UMVPA M1.04 compilation layer

This candidate adds `scalafim.fmri.mvpa.analysis`, an open compilation surface
for the recovered M1.01 evidence foundation. It deliberately leaves the legacy
`RoiAnalysis` / `MvpaEngine` surface untouched; the migration tickets own that
cutover.

The layer separates four facts:

1. `AnalysisSpecification.from` requires an open, method-owned
   `ScientificInputs` adapter. The native adapter derives the fingerprint from
   `Observations.identity`, `ValidationDesign.receipt`, and
   `MeasurementFrame.identity` (including measurement map fingerprints), plus
   the question, estimand parameters, assumptions, preparation, and reduction.
   It is metadata-only: it does not apply an evidence or measurement operator,
   materialize values, or hash payloads. `ScientificReceipt` contains no
   backend details and has controlled construction.
2. `AnalysisCompiler.bind` admits explicit method requirements only when both
   the actual source adapter and the supplied execution environment provide the
   capability. Native `Observations` conservatively report no replay capability:
   matrix-free observations can be one-shot, and representation does not certify
   replay. A caller-provided `replay` label therefore cannot admit such a source.
   `BoundScientificPlan` has controlled
   construction, preserving the compiler/specification relationship.
3. `NumericalProgram` declares the method-owned algorithm and sufficient
   statistics after binding.
4. `ExecutionPlan` adds backend, scheduling, chunking, and cancellation only
   after the numerical program exists.

`EvidenceReceipt` keeps a declared revision, verified read blocks, and verified
complete content separate. `RealizationReceipt` records implementation details;
neither is folded into `PlanId`.

`AnalysisResult.complete` accepts the bound estimand's path-dependent `Result`
type, so a `String` cannot complete a `Double` estimand. It returns global
artifacts directly and rejects a mismatched scientific receipt. Frame-valued methods use
`AnalysisResult[FrameResult[...]]`; each dependent entry retains `Unrequested`,
`Unsupported`, `NonEstimable`, `Failed`, `Cancelled`, `Partial`, or `Valid`.
Those states are not numerical zero.

`AccuracyReduction.pooledTrial` and `AccuracyReduction.meanRun` have distinct
return types and preserve contributing weights, exclusions, and denominators.
Empty contributors and duplicate contributor identities are typed reduction
outcomes, never `NaN` or silently omitted data. Pooled reductions retain exact
`BigInt` numerator/denominator sufficient statistics, so a total beyond
`Long.MaxValue` cannot be reported with a false zero denominator.
The owning tests use a test-only estimand and compiler instance, demonstrating
that no central enum, dispatch branch, or codec registry is required.

Focused compilation tests now cover source revision, realized split/seed, map
weight fingerprint, estimand parameters, schedule preservation, actual-source
capability admission, path-dependent result completion, polymorphic nominal
measurement outputs, and `Long` overflow. The final owning-module qualification is recorded below.
