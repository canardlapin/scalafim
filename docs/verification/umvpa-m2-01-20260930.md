# UMVPA M2.01 partitioned relations

Relation and RelationSet retain nominal effect, neural and partition witnesses.
The numeric relation is a Multivar Table; no domain-private solver is introduced.
Effect restriction composes the existing identified leg and preserves source,
preparation, access metadata and selected estimability. Relation.bindResidual
requires estimability, residual moments, precision and degrees-of-freedom
capabilities; missing capabilities fail at compilation rather than being invented
from readout rank. Source mismatch is rejected before capability callbacks.

IdentifiedReadoutRelations composes B = A Y after checking run/effect/feature
metadata. It does not construct a trial-image matrix. Declared acquisition,
response, readout, preparation and noise revisions are retained unchanged; a
separate metadata SHA-256 produces an id-safe value identity. This is declared
identity evidence, not a payload hash.

The adapter admits only explicit one-shot ReadoutResource ownership. withRuns
closes exactly its successfully acquired resources; rejected nested scopes cannot
close another invocation's readers. Every forward and adjoint access, including
restricted/escaped relations, shares the lifecycle guard. Reads and closure use
the same monitor. Every nonfatal close failure is captured while cleanup continues;
task and all close failures are retained. Failed acquire must clean any partial
acquisition itself. Replay is not inferred from a callable operator.

Tests cover dense/composed parity, metadata refusal, effect restriction, escaped
forward/adjoint refusal, nested scopes, later acquisition failure, multiple close
faults and foreign-source poison capabilities. No downstream crossnobis, RSA,
residual estimator or relation-query inference is claimed.

Owning JVM/JS gates and exact source/review evidence are in the integration report.
