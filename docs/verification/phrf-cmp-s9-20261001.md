## Current design in one paragraph

Commit-reveal: `root = SHA-256(v0_hash || beacon_A || secret)`; v0 commits `SHA-256(secret)`; the 32-byte secret exists only in the long-lived `session` process and in `secret.sealed` (encrypted to the owner key). The session derives and denylist-checks the root and hands root64 to the runner on an inherited pipe. Raw results are sealed at write time as self-contained blobs (fresh ephemeral X25519 key per blob, padded to size buckets, names encrypted, CLOSE record). The whitelist passes a strict schema with pooled df, 5-significant-figure rounding and degenerate-ICC handling. Checkout is a hook-free `git clone --no-hardlinks` of the reviewed SHA.

## New owner actions added by round 5

1. **Record the anchors off-machine at the moment they are printed**: `ANCHOR secret-commit: <seq>:<hash>` (when the session starts) and `ANCHOR v0: <seq>:<hash>` (when v0 is accepted; a recovered session prints a new one). Also record the `log head:` line printed after each action. Recovery is impossible without them.
2. For the real run use `--require-online`, and at the end check that the `v0` entry shows `network_checked: true`.
3. Pass `--log-anchor <seq>:<hash>` twice (secret-commit and v0) when recovering with `--secret-stdin`; use `--ack-timeout 600` for the cold JVM/sbt runner start.
4. A crash during `v0-wait` followed by a late v0 now voids the pilot (new v0 and new secret needed), by design.

## Items from earlier rounds that still hold

Whitelist schema `phrf-pilot-whitelist/2` (pooled df, 5 significant figures with sigma and `ucl80` up, degenerate coverage ICC, section-only error text); BLS verification required by default (`--allow-unverified` opts out); v0 binding (file equals committed bytes, hash and round equal the file's, round time after the commit date); `seeds.py` hash pinned in v0 and `seeds.root_from_sha256_hex` used; fingerprint check inside `seal_tree` and `SealedStore`; path-traversal guard on write and unseal; `git clone --no-hardlinks`, symlink and submodule refusal, `env -i` allowlist build, tool and lockfile hashes in the stamp; locked, fsynced, anchorable custody log.

## Design changes needed (for the coordinator)

- **4.1:** root includes the secret; v0 carries `secret_commitment`, `beacon_round`, `drand_chain_hash`, `seeds_py_sha256`; the denylist check runs inside the custodian session; ordering is enforced by the session's clock as well as by the commit date.
- **4.2/4.3:** the session holds the secret from before v0 to the end of the run and is lost by a reboot (recovery only via the owner's stdin); raw outputs are sealed at write time per the format spec; digests are over ciphertext; two off-machine copies of results, `secret.sealed`, log and stamp; checkout is a hook-free clone.
- **3.1/3.2:** whitelist emits one pooled `df` (minimum, at least 14); ICC entries `{icc, ucl80}` with `icc <= ucl80` and `"degenerate"` allowed for the coverage indicator; 5 significant figures, sigma and `ucl80` rounded up; schema id `/2`. Item 1 of 3.2 (`SealedStore.append`) is the Scala counterpart of the format spec's writer, including write-time read-back.
